# Архитектура SOLIK

## Компоненты

```
Telegram ──webhook──▶ api (Fastify)  ──▶ PostgreSQL (Prisma)
                         │  ▲
          REST /api/*    │  │ BullMQ
Web App (Next.js) ───────┘  ▼
                         worker ──▶ Telegram Bot API, Gemini
                           │
                         Redis (очереди, таймеры, кэш прав, rate limit)
```

- **api.** Принимает webhook'и всех ботов (`POST /webhook/:botId`) и обслуживает REST для Web App. Тяжёлые операции не выполняет: ставит их в очереди.
- **worker.** Обрабатывает очереди BullMQ: `ContestStartQueue`, `ContestEndQueue`, `WinnerQueue`, `GiftDeliveryQueue`, `TelegramNotificationQueue`, `AIContentQueue`, `AIImageQueue`, `SmsCounterQueue`, `AnalyticsQueue`, `AuctionTimerQueue`, `BroadcastQueue`, `SubscriptionQueue`. Если worker'ов несколько, их можно масштабировать горизонтально.
- **web.** Next.js. Запросы `/api/*` проксируются на api (rewrite), поэтому всё работает с одного origin, а cookie остаются first-party.

## Единая модель ботов

Главный бот SOLIK хранится в `TelegramBot` с `isPlatform=true`, `ownerId=null`. White-Label боты — это строки той же таблицы с владельцем. Поэтому все механики (чаты, конкурсы, SMS, перебивка, выдача) работают одинаково для обоих видов ботов. Различается только UX в личных сообщениях:

- главный бот показывает меню SOLIK;
- White-Label бот показывает приветствие, меню и медиа владельца, без бренда SOLIK.

Тарифная модель:

- **Free** — бот SOLIK в чатах пользователя, все функции.
- **White-Label** — собственный бот за `WhiteLabelPlan.priceStars` (по умолчанию 100 ⭐ / 30 дней). Цена меняется в админ-панели.

Владелец чата для главного бота — пользователь, который добавил бота (`my_chat_member.from`). У White-Label бота это владелец бота.

## Поток обработки обновления

1. `webhook.ts` сверяет `X-Telegram-Bot-Api-Secret-Token` с секретом бота (timing-safe).
2. Создаёт `WebhookEvent(botKey, updateId)`. Уникальный индекс даёт **идемпотентность**: повтор от Telegram возвращает 200 без обработки.
3. `dispatcher.ts` направляет обновление по типу: `pre_checkout_query`, платежи, `my_chat_member`, `business_connection`, `channel_post`, автопересылки постов в группу обсуждения, команды `.sms`, кубики 🎰, платные сообщения, активность.
4. Ответ всегда 200: одно сломанное обновление не блокирует поток бота. Ошибка записывается в `WebhookEvent.error`.

## Конкурентность и надёжность

| Место | Механизм |
|---|---|
| SMS Counter | `SELECT … FOR UPDATE` строки счётчика, позиции строго последовательны |
| Перебивка | блокировка строки конкурса, повторная валидация ставки в транзакции, уникальный `telegramPaymentChargeId` |
| Winner Engine | блокировка + условный переход статуса, повторный вызов невозможен; перевыбор — отдельная операция |
| Мгновенные призы | лимит `drawsCount < winnersCount` под блокировкой, один приз на пользователя |
| Выдача призов | идемпотентный ключ; если сбой случился в `PROCESSING`, повторной отправки не будет — статус `MANUAL_REQUIRED` |
| Подписки | идемпотентность по `telegram_payment_charge_id` |
| Рассылки | `@@unique([broadcastId, chatTgId])` — дедупликация; jobId = id получателя |

### Таймеры

Источник истины — `Contest.endsAt` и `timerVersion` в PostgreSQL. Отложенные задачи BullMQ имеют детерминированные jobId вида `(contest, version, kind, secondsLeft)`. Каждая ставка увеличивает `timerVersion`, и старые задачи становятся no-op. При старте worker вызывает `recover()`: переназначает таймеры, запланированные конкурсы, рассылки и выдачи. После перезапуска сервера конкурсы продолжают работу.

## Режимы конкурсов

| Тип | Механика |
|---|---|
| `RANDOM` / `GIFTS` / `NFT` | кнопка «Участвовать» (callback), проверка обязательных подписок через `getChatMember` |
| `STARS_AUCTION` | `bidMode=invoice`: Stars-инвойс боту, ставка засчитывается только после `successful_payment`; проигравшие гонку получают автоматический возврат. `bidMode=paid_messages`: сообщение с `paid_star_count>0` в чате с платными сообщениями. Предупреждения за 60/30 с, отсчёт 10…1 |
| `FIRST_COMMENT` | связь пост → ветка через автопересылку в группу обсуждения (`is_automatic_forward`), учитываются только комментарии этой ветки |
| `SMS_COUNTER` | `.sms N`; в ветке комментариев считаются комментарии поста, в группе — сообщения группы |
| `MESSAGE_GIVEAWAY` | каждые N (случайному активному или автору), шанс % на сообщение с дневным лимитом, порог, первое сообщение |
| `ACTIVITY` | лидерборд за период: самый активный, случайный, взвешенный, по порогу |
| `DICE_777` | 🎰 со значением 64; пересланные кубики игнорируются |

## Ограничения Telegram и принятые решения

| Ограничение | Решение |
|---|---|
| Bot API не создаёт ботов | пользователь создаёт бота в @BotFather и передаёт токен; токен шифруется, сообщение с ним удаляется |
| Username бота меняется только в BotFather | имя, описание, команды и меню применяются через `setMyName`/`setMyDescription`/`setMyCommands`. Для аватара вызывается `setMyProfilePhoto`; если метод недоступен — подсказка про `/setuserpic` |
| Бот не может перевести Stars пользователю | приз «Stars» → ручная выдача с уведомлением владельцу (либо замена подарком) |
| Коллекционные подарки бот не покупает | передача из аккаунта владельца через Telegram Business (`transferGift`) или вручную |
| Наличие ID подарка ≠ возможность отправки | регулярная сверка с `getAvailableGifts`, только подтверждённые → `BOT_SEND_GIFT` |
| Premium Emoji у ботов разрешены не везде | отправка с `<tg-emoji>`; при отказе Telegram — автоматический повтор с fallback-символами |
| Бот видит посты канала только после добавления | для First Comment бот публикует пост сам или берёт пост из сохранённых |
| Бот не видит сообщения группы в privacy mode | бот должен быть администратором (или privacy выключен в BotFather) |
| Автопродление Stars-подписок — только 30 дней | для других периодов продление ручное |
| Лимиты отправки (~30 msg/s, ~20 msg/min в группу) | глобальный limiter очередей, обработка 429 `retry_after` с паузой всей очереди |
